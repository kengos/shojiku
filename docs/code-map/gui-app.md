> AI-only, token-dense. Index + repo-wide conventions: [CLAUDE.md](../../CLAUDE.md).

> Granularity: file role + key exports + load-bearing contracts.

`gui/designer-app/` — **the standalone shell** (Vite build, the first
shipping form): a locale-keyed preset catalog opening into the embedded
`Designer`. Pure orchestration over injected services (App is ONE host of
the component); every browser concern is a dependency-injected module
carrying the 100%×4 gate, and the browser-entry group
(`src/main.tsx` + `src/browser/`, both coverage-excluded) is the ONLY
place real browser globals (fetch/navigator/localStorage/wasm) are
wired: `main.tsx` keeps the COMPOSITION (which module gets which global,
in which order) over one module per browser surface — `browser/io.ts`
(the two fetch readers, the file-picker dialog, the download trigger),
`browser/imageCodec.ts` (the `<img>`/`<canvas>` `ImageCodec`),
`browser/dataSources.ts` (`makeLoadPreset` over the assembled `data/`
tree + the `config.json` mount probe), `browser/enginePrep.ts`
(`makePrepareEngine`: await the module promise → `pickerCapable` →
boot → lazy loader → the capability-gated `FontController`;
`makeSpecimen`), `browser/moduleFetch.ts` (`fetchWasmModule`: the
`fetch` call only — the progress observation is the covered
`loading/observe.ts`), `browser/faker.ts` (the per-locale
dynamic-import map).
**Boot is catalog-first**: `main.tsx` starts the module fetch and does
NOT await it before the first render (the await is inside
`prepareEngine`, i.e. the first preset open), so the catalog paints
without the ~1.7 MB module; `index.html` carries an inline static splash
(literal colours — it renders before any token exists). Policy:
[docs/agents/gui.md](../agents/gui.md); mounted-host wire:
docs/designer-mount.md; hook registry: docs/designer-hooks.md.

## Assets + engine boot (`src/assets/`, `src/engine/`)

- `assets/manifest.ts` — type-only: the assembled `catalog.json` /
  `fonts/index.json` / `locale/index.json` shapes (`CatalogPreset` incl.
  `variants` + `assets`; `FontIndex` with per-pack tier primary|lazy;
  `LocaleIndex`). `assets/paths.ts` — `isSafeAssetName` charset guard +
  `thumbnailUrl` (runtime re-check, defense-in-depth over the build).
- `engine/wasmModule.ts` — coverage-excluded: `WasmFullEngine` interface
  + `loadWasmModule` (dynamic import of the gitignored pkg).
- `engine/boot.ts` — `bootEngine` (pure over injected engine +
  `FontSource`): capability gate, `setLocale(tag, overlay)`, inject
  PRIMARY-tier needed packs, `loadFontsSubset`; returns
  `{absentPackIds, packIds, familyIds, defaultFamily}` — the full
  re-inject set (the engine CONSUMES injected packs per load), the
  family-dropdown seed, and the locale's default family. Optional
  `onProgress` reports the face transfer as `{loaded, total}`, the total
  summed from the INDEX before the first fetch (monotonic by
  construction; discovering it pack-by-pack would walk the ratio
  backwards) and a face the index lacks counted as zero.
- `engine/families.ts` — pure family extraction over guarded YAML parse
  + `defaultFamilyFrom` (`===`-matched, hostile ids inert).
- `engine/fontSource.ts` / `localeSource.ts` / `assetSource.ts` /
  `variantSource.ts` — the four injected-fetch loaders (manifest+face
  bytes with `.partNN` reassembly / locale-pack overlay text / preset
  asset bytes / preset sample variants), each name/id re-guarded at
  runtime and size-capped; the engine parses/validates — these only
  decide existence and fetch. Asset injection (`EnginePrep.injectAssets`
  → `addAssetFile('assets/<name>', …)`) is session-RETAINED, unlike
  load-consumed font packs.
- `engine/lazyFonts.ts` — `LazyFontLoader` (fetch→inject→reload,
  single-flight; trigger = (`missing_glyph` OR `unknown_font_family`) ∩
  non-empty absent set; re-injects the FULL pack set — `packIds` is a
  FUNCTION read per run because the set grows after boot) +
  `ensureLoaded()` (the FORCED load the PDF path takes — a failed load
  REFUSES the render, never a silently degraded PDF) +
  `createLazyFontTransport` (an upgrade swaps transport identity → the
  preview re-renders).

## First-load experience (`src/loading/` — all 100%-covered, no browser globals)

- `progress.ts` — `ByteProgress` (`{loaded, total?}`) + `readProgress`:
  the ONE place an unusable reading degrades. Returns `null`
  (indeterminate) for an absent/non-finite/non-positive total or a
  non-finite `loaded`; otherwise clamps `loaded` into `[0, total]` and
  yields `{ratio, percent, loadedText, totalText}`. Byte text is DECIMAL
  MB/KB (the label says MB, so the division must too).
- `moduleLoad.ts` — the app-global module transfer as a
  `useSyncExternalStore` source: `ModuleLoad` =
  `loading{bytes} | ready | failed`, `moduleLoadTracker()` with
  `expect(total)` / `advance(chunkBytes)` / `finish()` / `fail()`.
  `ready`/`failed` are TERMINAL (a straggling chunk cannot reopen the
  view); `get()` returns a stable reference between changes.
  `parseContentLength` accepts ONLY `/^\d+$/` + safe-integer + `> 0` —
  `Number()` is far too lenient for a header (`''`, `'0x10'`, `'1e6'`,
  `'Infinity'`, padded) and a wrong total is worse than no total.
- `observe.ts` — `observeResponse(res, tracker)`: what an already-fetched
  module `Response` MEANS — declares the parsed `Content-Length`, re-wraps
  the body so each delivered chunk advances the tracker while the bytes
  pass through un-buffered (streaming compile preserved; headers/status
  ride along — `instantiateStreaming` needs the `application/wasm`
  content-type), returns a body-less response AS-IS, and delegates
  cancel. Pure over an injected `Response`; the `fetch` stays in
  `browser/moduleFetch.ts`.
- `phase.ts` — the wait as three named stages: `LoadPhase` =
  `engine{bytes} | fonts{bytes} | render | failed{stage}`, `OpenStep`
  (what an open flow reports: `fonts{bytes}` → `prepared`, or `failed`),
  `phaseOf(load, step)` (module failure wins, then an open refusal → the
  fonts stage, then the module wait, then the flow's report),
  `activeStage`, `stageViews` (earlier = done, later = todo), and
  `phaseReading`.
- `ProgressBar.tsx` — the one bar, two heights; `aria-valuenow` present
  ONLY when determinate, indeterminate fills the track with
  `motion-safe:animate-pulse`. `LoadingView.tsx` — the preset-open panel
  (document name + stage rows + byte counts on the active transfer + the
  percentage, or the failure and its remedy in place of the bar); used by
  BOTH bodies. `EngineLoadBar.tsx` — the catalog-time chrome:
  `EngineLoadBar` (hairline rail under the header) + `EngineLoadStatus`
  (the header's muted line), both nothing once the module is in.

## Persistence (`src/persistence/` — implementations; the seam TYPES live in `@shojiku/designer` `registry/`)

- `storedDoc.ts` — the untrusted payload-field vocabulary, shared
  because the draft, snapshot and mounted-host readers all take values
  of these shapes: `isInstalledFont` (a font entry is MANIFEST fields
  only — read by all three), `parseStoredSample` (the sample-variant
  set: caps, duplicate-id reject, `active` must name a variant;
  malformed = `null`, so the caller misses cleanly rather than
  partially restoring — draft + snapshot), and `isString` (draft +
  host readers).
- `draftEnvelope.ts` — what a stored draft IS, both directions:
  `Draft`, `buildEnvelope` (current v6) and `parseEnvelope` (the v1…v6
  read ladder — v6 = text + font pins (never bytes) + optional
  rev/rename + the sample-variant set + working definitions + the
  `definitionsEdits` op list, sanitized on read; older versions
  upgrade, malformed fields = a clean miss).
- `drafts.ts` — `DraftStore` (TemplateStore over injected `Storage`):
  the LOCAL working-copy store — the key namespace and the
  save/load/clear around the envelope; quota → typed outcome, a
  corrupted entry is pruned on read.
- `snapshotEntry.ts` — one restore point: `Snapshot`/`SnapshotDraft` +
  `parseSnapshot` (untrusted entry guard; over-long name CLIPPED, bad
  id/createdAt/text/fonts/sample = `null`).
- `snapshots.ts` — `SnapshotStore` (the named-restore-point RING, key
  separate from the draft so a point survives draft-clear; capture
  REFUSES at `MAX_SNAPSHOTS` — never silently evicts; list drops
  invalid entries and prunes a corrupted envelope).
- `blocks.ts` — `BlockStore` (APP-GLOBAL single key, cross-document;
  `sanitizeBlocks` on load; quota → typed outcome).
- `httpIds.ts` — the seam's id vocabulary: `isSafeId` (charset +
  length, checked BEFORE any URL composition) and the
  `<projectId>/<templateId>` doc key (`docKey`/`splitKey`).
- `httpReaders.ts` — what a host RESPONSE means: `parseBody` (body cap)
  + one reader per payload (`readSummaries`/`readProject`/`readDoc`/
  `readSavedRev`), every field runtime-guarded and every list capped;
  malformed = `null`.
- `http.ts` — `HttpStore` (TemplateStore+ProjectSource+DefinitionsStore)
  — the mounted host's CLIENT: routes + fail-closed outcomes
  (`credentials: 'same-origin'` — auth is the proxy's; 409 → conflict;
  a network throw or non-2xx → typed error); `saveDefinitions` PUTs
  `projects/{id}/definitions`.
- `prefs.ts` — locale/theme/grid-step/size-cap/pane-width prefs
  (accessor-read per mount, validated/clamped — user-writable storage
  never reaches a CSS var) + `tutorialStore()` (raw string on purpose —
  only the component knows real step ids).
- `files.ts` — size-capped `openText` + sanitized export filenames
  (`buildExport`/`buildPdfExport` — stem guard collapses dot runs).

- `app/MountedApp.tsx` — the mounted body's RENDER TREE: project list →

  (edit ops re-apply over the live host base; explicit save via

  view vocabulary + the remote reads (`useMountedNav`): open = parallel
  load + engine prep, then draft check; back re-fetches the project;
  every read carries its own `retry` closure, so the error view
  re-enters exactly the read that failed. `app/MountedLists.tsx` — the
  two list views over one `EntryList` + the localized error state.
- `EditorScreen.tsx` + `app/editorWiring.ts` — the per-document
  ASSEMBLY, split composer/render-tree the way `designer` splits
  `wiring.ts`/`Designer.tsx`: `useEditorWiring` owns the hook-call
  order (synth load FIRST (`app/useSynthLoad.ts`), `useFontInstall`
  next, the header report LAST (`app/useHeaderReport.ts`) — effect
  order is load-bearing and unchanged by the split); `EditorScreen.tsx`
  owns only the render tree; `app/editorProps.ts` carries
  `EditorScreenProps`. Keyed by `docKey`; state in
  `app/useWorkingCopy.ts`; actions in `app/editorActions.ts` (a PURE
  factory — extracting them moved no effect). Threads
  `services.copilot` and `prep.capabilities` (the ACTUAL engine's keys)
  to the Designer; feeds the File menu via `menuActions` (incl.
  `onDownloadPdf` routing engine bytes to the same download seam);
  holds the app-global block library; derives
  `definitionsProjectScoped`; reports name/save-status/rename up to the
  app header (`customName ?? documentName`; a standalone rename to
  exactly `documentName` clears it).
- `app/draftSave.ts` — pure over an explicit `DraftContext`: the ONE
  home for the local draft envelope (`pristineWith` baselines on
  `files.source`, never the restored seed — clearing a pristine draft
  can never lose unregenerable content; `buildDraft`/`saveDraft`).
  `DraftOver` members are optional ON PURPOSE (`'key' in over`
  distinguishes clearing from untouched); **`fonts` is an ACCESSOR,
  not a snapshot** (picks persist after their async install settles).
- `app/useHostSave.ts` — where an explicit save lands: standalone =

  `TemplateStore.save` with the tracked rev (409 keeps the working
  copy); definitions PUT only AFTER the template save and only while
  differing. A monotonic edit counter captured at dispatch keeps
  "Saved." honest; `noteEdit()` is the one entry point.
- `app/useFontInstall.ts` — fonts for one mount: the lazy transport
  wrapper, the picked-font flow, the narrowed `picker` gate, and BOTH
  font restores (draft on mount; `restoreFonts(fonts, onDone)` — the

  `missing_glyph` previews behind a localized banner.
- `app/useSnapshots.ts` — the restore-points dialog state + store I/O
  (the RESTORE itself stays with the document state it reseeds).
- `app/EditorBanners.tsx` — the error-class status strip
  (`saving`/`saved` deliberately absent — the app header owns them).
- `app/sampleEdited.ts` / `app/pristine.ts` — the pure export-kit and
  pristine predicates.

## Build / assemble / deploy / dev

  `planFace`/`partNames` (>20 MiB chunked), `packTier` (>25 MiB → lazy),

  repo mount (builds wasm if absent, runs assemble);
